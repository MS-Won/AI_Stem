# MS Audio (가칭) 운영 체계

설계: `docs/superpowers/specs/2026-11-26-ms-audio-org-design.md`. 조직은 출시를 빠르게 하기 위한 도구다. 출시가 가장 중요하다.

## 부서
| 부서 | 에이전트 | 하는 일 |
|---|---|---|
| 기획실 | 메인 세션 | 대표 지시를 나눠 맡기고, 로드맵·STATE·todo 관리, 대표 보고서 작성 |
| 디자인팀 | `design` | 브랜드 기초, 화면 시안, 랜딩 문구 (승인 전 구현 금지) |
| 개발팀 | `developer` | `web/`, GPU 워커, 엔진 연결. TDD |
| 연구소 | `research` | 엔진 개선 연구. 대표 청취 승인 없이 엔진 변경 금지 |
| 품질팀 | `qa` | 리뷰, 테스트, 배포 URL 점검. 고치지 않고 보고만 |
| 감사실 | `auditor` | 셀프 피드백: 첫 1원·출시 기간에서 벗어났는지 점검 (읽기 전용) |

## 일하는 흐름
1. 세션 시작: 기획실이 `docs/STATE.md`의 `## 대표 확인`과 최신 보고서를 읽고, 대기 중인 결정부터 묻는다.
2. 대표 지시 → 부서별 작업. 새 기능은 설계 → 계획 → 개발.
3. 개발 결과는 품질팀 리뷰를 거친다.
4. 큰 작업 단위가 끝나면 감사실 점검.
5. 기획실이 보고서(`reports/YYYY-MM-DD-<주제>.md`, 형식은 `reports/_template.md`) 작성 → `decisions.md`·STATE·todo 갱신 → 커밋 → push.

## 알림
- 세션 중: 긴 작업 완료·대표 결정 필요 시 휴대폰 Claude 앱 푸시.
- 세션 밖: 평일 오전 9시 예약 작업이 GitHub main의 STATE.md와 최신 보고서를 읽고 푸시 (아래에 예약 작업 이름 기록).
